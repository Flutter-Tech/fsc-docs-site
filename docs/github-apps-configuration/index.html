GitHub Apps configuration

Codebase governor lets you define GitHub Apps configuration in a YAML file.

This public content is an excerpt from Flutter staff GitHub docs. It is published as a reference to show how GitHub is used for inner source at Flutter.

This page explains the format of the Codebase Governor GitHub App configuration file. All fields are mandatory unless otherwise specified.

The file uses YAML syntax, and must have a .yml file extension. The filename must match the GitHub App name as a slug. i.e.: My GitHub App -> my-github-app.yml.

If you’re new to YAML and want to learn more, see “Learn YAML in Y minutes”.

owners

The owners key specifies the owner of a GitHub App. It supports two sub-keys:

  • users: An array of GitHub usernames who are the owners of the GitHub App.
  • teams: An array of GitHub team names that own the GitHub App.
owners:
  users: ["crisostomon"] # List of GitHub usernames of the GitHub App owners (string array)
  teams: ["maintainers-cap-codebase-governor"] # List of GitHub team names that own the GitHub App (string array)

description

The description key contains a brief description of the GitHub App. It should be a single sentence or a few short sentences, but not more than one paragraph (i.e., it shouldn’t contain line breaks).

description: "Allows read-only cross-repo access in GitHub Action workflows" # Brief description of the GitHub App (string)

contacts

The contacts key provides contact information for the GitHub App. It has two sub-keys:

  • slack: An array of Slack channel names where users can reach out for inquiries about the GitHub App.
  • email: An array of email addresses for contacting the GitHub App owners team.
contacts:
  slack: ["inner-source"] # List of Slack channel names for contact (string array)
  email: ["AlphaOpsTeam@flutter.com"] # Email addresses for contact (string array)

url

The url key specifies the URL of the pull request in the org-config repository where the GitHub App configuration file was submitted for review. This allows for easy reference to the original request and any related discussions or approvals.

url: "https://github.com/Flutter-Global/org-config/pull/123456" # URL of the GitHub App configuration file pull request (string)

source

The source key indicates the origin of the GitHub App.

Available values:

  • Flutter-Global: The app is developed and maintained internally.
  • marketplace: The app is sourced from the GitHub Marketplace.
source: "Flutter-Global" # Source of the GitHub App, either Flutter-Global or marketplace (string)

skip_repo_usage_approval

The skip_repo_usage_approval key indicates whether an approval is needed when adding an app to a repository configuration file, or to a defaults config in a capability. Even if set to true, an approval will still be needed if the app file is changed.

Available values:

  • true: The app doesn’t request an approval from an owner when adding to a repository/defaults config.
  • false: The app requests an approval from an owner when adding to a repository/defaults config.
skip_repo_usage_approval: true # (boolean)

permissions

The permissions key defines the access levels the GitHub App requires for various resources. There are four main categories of permissions:

  • repository: The permissions the app requires for accessing repository content, including code, issues, pull requests, and more.
  • organization: The permissions the app requires for accessing organization-level resources, such as teams and members.
  • user: The permissions the app requires for accessing user-specific resources, such as profile information and repositories.
  • business: The permissions the app requires for accessing business-specific resources, such as billing and usage data.

permissions.repository

The permissions.repository key specifies the access levels the GitHub App requires for various repository resources.
Each resource can have only one of the following access levels: read, write, or (where noted) admin.

Available Repository Permissions

  • actions (read, write)
    Allows the app to read or write GitHub Actions workflows and related data.

  • actions_variables (read, write)
    Allows the app to read and modify GitHub Actions variables in a repository.

  • administration (read, write)
    Allows the app to read and manage repository settings, including collaborators, teams, and webhooks.

  • attestations (read, write)
    Allows the app to read and write supply chain attestations for repositories.

  • checks (read, write)
    Allows the app to read and write check runs and check suites.

  • codespaces (read, write)
    Allows the app to manage Codespaces and their settings.

  • codespaces_lifecycle_admin (read, write)
    Allows the app to manage the lifecycle of Codespaces, including creation and deletion.

  • codespaces_metadata (read, write)
    Allows the app to read and write metadata for Codespaces.

  • codespaces_secrets (read, write)
    Allows the app to read and manage Codespaces secrets.

  • contents (read, write)
    Allows the app to read and write repository code, including files, branches, and tags.

  • dependabot_secrets (read, write)
    Allows the app to read and manage Dependabot secrets for a repository.

  • deployments (read, write)
    Allows the app to read and manage deployment statuses and deployment environments.

  • discussions (read, write)
    Allows the app to read and manage GitHub Discussions posts, comments, and categories.

  • environments (read, write)
    Allows the app to read and manage repository environments, including environment secrets.

  • issues (read, write)
    Allows the app to read and manage issues, including creating, editing, and closing issues.

  • merge_queues (read, write)
    Allows the app to read and manage merge queues for pull requests.

  • metadata (read, write)
    Allows the app to access repository metadata, such as repository name, description, and topics.

  • packages (read, write)
    Allows the app to read and manage GitHub Packages published to a repository.

  • pages (read, write)
    Allows the app to read and manage GitHub Pages sites and settings.

  • pull_requests (read, write)
    Allows the app to read and manage pull requests, including creating, updating, and merging.

  • repo_secret_scanning_dismissal_requests (read, write)
    Allows the app to read and manage requests to dismiss secret scanning alerts in a repository.

  • repository_advisories (read, write)
    Allows the app to read and manage security advisories for a repository.

  • repository_custom_properties (read, write)
    Allows the app to read and manage custom properties for a repository.

  • repository_hooks (read, write)
    Allows the app to read and manage repository webhooks.

  • repository_projects (read, write, admin)
    Allows the app to read, manage, and administer repository projects (classic).

  • secret_scanning_alerts (read, write)
    Allows the app to read and manage secret scanning alerts in a repository.

  • secret_scanning_bypass_requests (read, write)
    Allows the app to read and manage requests to bypass secret scanning in a repository.

  • secrets (read, write)
    Allows the app to read and manage repository secrets.

  • security_events (read, write)
    Allows the app to read and manage security events in a repository.

  • single_file (read, write)
    Allows the app to read and write a single file in a repository.

  • statuses (read, write)
    Allows the app to read and write commit statuses.

  • vulnerability_alerts (read, write)
    Allows the app to read and manage Dependabot alerts for vulnerable dependencies.

  • workflows (read, write)
    Allows the app to read and manage GitHub Actions workflows.

permissions.organization

The permissions.organization key specifies the access levels the GitHub App requires for various organization resources.
Each resource can have only one of the following access levels: read, write,or (where noted) admin.

Available Organization Permissions

  • issue_fields (read, write)
    Allows the app to read and manage custom fields for issues in the organization.

  • issue_types (read, write)
    Allows the app to read and manage custom issue types in the organization.

  • members (read, write)
    Allows the app to read and manage organization members.

  • organization_api_insights (read, write)
    Allows the app to access API insights for the organization.

  • organization_actions_variables (read, write)
    Allows the app to read and manage organization-level GitHub Actions variables.

  • organization_administration (read, write)
    Allows the app to read and manage organization settings.

  • organization_announcement_banners (read, write)
    Allows the app to read and manage announcement banners for the organization.

  • organization_campaigns (read, write)
    Allows the app to read and manage organization campaigns.

  • organization_code_scanning_dismissal_requests (read, write)
    Allows the app to read and manage code scanning dismissal requests at the organization level.

  • organization_codespaces (read, write)
    Allows the app to manage Codespaces for the organization.

  • organization_codespaces_secrets (read, write)
    Allows the app to read and manage organization-level Codespaces secrets.

  • organization_codespaces_settings (read, write)
    Allows the app to read and manage Codespaces settings for the organization.

  • organization_copilot_seat_management (read, write)
    Allows the app to manage GitHub Copilot seat assignments for the organization.

  • organization_custom_org_roles (read, write)
    Allows the app to read and manage custom organization roles.

  • organization_custom_properties (read, write, admin)
    Allows the app to read, manage, and administer custom properties for the organization.

  • organization_custom_roles (read, write)
    Allows the app to read and manage custom roles for the organization.

  • organization_dependabot_secrets (read, write)
    Allows the app to read and manage organization-level Dependabot secrets.

  • organization_events (read, write)
    Allows the app to read and manage organization events.

  • organization_hooks (read, write)
    Allows the app to read and manage organization webhooks.

  • organization_knowledge_bases (read, write)
    Allows the app to read and manage knowledge bases for the organization.

  • organization_models (read, write)
    Allows the app to read and manage models for the organization.

  • organization_network_configurations (read, write)
    Allows the app to read and manage network configurations for the organization.

  • organization_personal_access_token_requests (read, write)
    Allows the app to read and manage personal access token requests for the organization.

  • organization_personal_access_tokens (read, write)
    Allows the app to read and manage personal access tokens for the organization.

  • organization_plan (read, write)
    Allows the app to read and manage the organization’s plan and billing information.

  • organization_private_registries (read, write)
    Allows the app to read and manage private registries for the organization.

  • organization_projects (read, write, admin)
    Allows the app to read, manage, and administer organization projects (classic).

  • organization_secret_scanning_bypass_requests (read, write)
    Allows the app to read and manage requests to bypass secret scanning at the organization level.

  • organization_secrets (read, write)
    Allows the app to read and manage organization secrets.

  • organization_self_hosted_runners (read, write)
    Allows the app to read and manage self-hosted runners for the organization.

  • organization_user_blocking (read, write)
    Allows the app to read and manage user blocking for the organization.

  • secret_scanning_dismissal_requests (read, write)
    Allows the app to read and manage secret scanning dismissal requests at the organization level.

  • team_discussions (read, write)
    Allows the app to read and manage team discussions.

permissions.user

The permissions.user key specifies the access levels the GitHub App requires for various user resources. Each resource can have one of the following access levels: read or write.

  • blocking (read, write)
    Allows the app to read and manage users blocked by the authenticated user.

  • codespaces_user_secrets (read, write)
    Allows the app to read and manage Codespaces user secrets.

  • copilot_editor_context (read, write)
    Allows the app to read and manage Copilot editor context for the user.

  • copilot_messages (read, write)
    Allows the app to read and manage Copilot messages for the user.

  • emails (read, write)
    Allows the app to read and manage email addresses for the user.

  • followers (read, write)
    Allows the app to read and manage followers for the user.

  • gpg_keys (read, write)
    Allows the app to read and manage GPG keys for the user.

  • gists (read, write)
    Allows the app to read and manage gists for the user.

  • git_signing_ssh_public_keys (read, write)
    Allows the app to read and manage Git signing SSH public keys for the user.

  • interaction_limits (read, write)
    Allows the app to read and manage interaction limits for the user.

  • keys (read, write)
    Allows the app to read and manage SSH keys for the user.

  • knowledge_bases (read, write)
    Allows the app to read and manage knowledge bases for the user.

  • plan (read, write)
    Allows the app to read and manage the user’s plan and billing information.

  • profile (read, write)
    Allows the app to read and manage the user’s profile.

  • starring (read, write)
    Allows the app to read and manage repositories starred by the user.

  • user_events (read, write)
    Allows the app to read and manage user events.

  • user_models (read, write)
    Allows the app to read and manage models for the user.

  • watching (read, write)
    Allows the app to read and manage repositories watched by the user.

permissions.business

The permissions.business key specifies the access levels the GitHub App requires for various business resources.
Each resource can have only one of the following access levels: read or write.

  • enterprise_custom_properties (read, write)
    Allows the app to read and manage custom properties for the enterprise.

  • enterprise_organization_installation_repositories (read, write)
    Allows the app to read and manage repositories installed for the enterprise organization.

  • enterprise_organization_installations (read, write)
    Allows the app to read and manage organization installations for the enterprise.

  • enterprise_organizations (read, write)
    Allows the app to read and manage organizations within the enterprise.

  • enterprise_people (read, write)
    Allows the app to read and manage people within the enterprise.

  • enterprise_sso (read, write)
    Allows the app to read and manage single sign-on (SSO) settings for the enterprise.
